# issgen Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A Python CLI that generates Juki ISS placement programs (`Program.iss`) from an Altium pick-and-place CSV, a YAML panel definition, and the DETEX.mdb component database — replacing CircuitCAM Express.

**Architecture:** Pipeline: pydantic-validated YAML config + CSV parser + DB reader → an in-memory `BuildModel` → geometry checks (`--check`) → lxml emitters producing the minimal ISS skeleton proven to open in JaNets → XSD + semantic validation before any byte is written. All numbers are `Decimal` end-to-end (never float) to avoid CircuitCAM-style conversion noise.

**Tech Stack:** Python 3.11+ (3.14 on this machine), `lxml`, `pyodbc`, `pydantic` v2, `pyyaml`, `click`, `pytest`.

### Design decisions already made (do not reopen)
1. Emit ONLY the Program.iss skeleton: `headerData`, `core`, `model`, `machine` (bocMarkData only). No `leadInformation`, no `centering`, no `bocExtMark` (off-by-default flag `--emit-boc-ext` exists but does nothing in v1 except raise "not implemented").
2. Misspellings `witdh`, `connecterHeight`, `TemplateLink` are emitted verbatim; a test locks this in.
3. `lineName` defaults to `Line` id=`1` (JaNets values), never `Aegis`.
4. Group markName: `BOCMARK01` (JaNets style, not CircuitCAM's `#`).
5. Frame default `circuit_relative` (JaNets convention): Altium coordinates pass through unchanged into `placementPosition`; `machine.circuit_layout_offset` relates the CAD origin to the machine frame. `panel_absolute` is accepted as config but only changes what `--check` tests containment against.
6. Every number is `decimal.Decimal` from parse to emit. DB units 0.1 µm ÷ 10000 (Decimal division, exact).
7. Golden/round-trip reproducibility: `issgen build --timestamp 2026-07-31T12:00:00` overrides `lastEdit`.
8. The XSD ships inside the package (`issgen/data/iss_schema_0.xsd`) so `build` always validates; `issgen validate --schema` can override.
9. Bottom-side path: implemented (mirror y across panel X axis: `y' = outline.y − y`, angle `(360 − a) % 360`), gated behind `pnp.side: bottom`, and always prints a loud UNTESTED warning. Do not silently trust it.
10. Empty fiducial slots emit `<markName />` and `<markPosition x="0" y="0" />` (schema-clean; JaNets zeros its empties).

```python
"""ISS byte-format layer: Decimal→string and lxml tree→JaNets-style bytes."""
from decimal import Decimal
from lxml import etree

def fmt(value: Decimal | int) -> str:
    d = Decimal(value)
    if d == 0:
        return "0"
    if d == d.to_integral_value():
        return str(d.quantize(Decimal(1)))
    return format(d.normalize(), "f")

def serialize(root: etree._Element) -> bytes:
    for el in root.iter():
        for v in el.attrib.values():
            if "/>" in v:
                raise ValueError(f"attribute value {v!r} would corrupt self-closing-tag rewrite")
    etree.indent(root, space="  ")
    body = etree.tostring(root, encoding="unicode")
    body = body.replace("/>", " />")
    text = '<?xml version="1.0" encoding="utf-8"?>\n' + body + "\n"
    return b"\xef\xbb\xbf" + text.replace("\n", "\r\n").encode("utf-8")
```

Note: `etree.indent` leaves self-closing tags as `<tag/>`; the replace turns them into `<tag />`. `fmt(Decimal("1E+6"))` path: `quantize(Decimal(1))` renders `1000000` without exponent — that is what the first no-scientific test pins down. If `quantize` raises for huge values it's fine — coordinates are < 10^4.

**Design:** `@dataclass Part(name, comment, witdh: Decimal, length: Decimal, height: Decimal, connecter_height: Decimal, component_type: str)`. Two loaders returning `dict[str, Part]` keyed by CompoName:
- `load_cache(json_path)` — reads the JSON snapshot.
- `load_mdb(mdb_path)` — pyodbc, `SELECT c.CompoName, c.Description, c.Width, c.Length, c.Height, c.ConHeight, c.PkgClassID, p.EngClass FROM Compo c LEFT JOIN PkgClass p ON c.PkgClassID = p.PkgClassID`. - `get_parts(db_cfg) -> dict[str, Part]` — cache if configured and exists, else mdb, else `DetexError`.
- `connect(mdb_path)` — builds conn string `DRIVER={Microsoft Access Driver (*.mdb, *.accdb)};DBQ=...`. On `pyodbc.InterfaceError`/`Error`: raise `DetexError` explaining (a) Python bitness (`struct.calcsize('P')*8`), (b) installed Access drivers (`pyodbc.drivers()` filtered on 'Access'), (c) the fix: install matching-bitness Access Database Engine redistributable or use `--db-cache`.
